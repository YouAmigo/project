# Функциональные требования

## Назначение

Документ описывает, что должен делать Study Planner Bot.

Требования разделены на:

- **MUST** — обязательно для MVP;
- **SHOULD** — желательно после MVP;
- **NICE** — можно реализовать позже.

---

## MUST-1. Загрузка `.ics`

Пользователь отправляет боту файл расписания.

### Критерии приёмки

- бот принимает только `.ics`;
- файл сохраняется в `app/data`;
- пользователь получает сообщение об успешной загрузке;
- если формат неверный, бот пишет: `Нужно загрузить файл .ics`.

---

## MUST-2. Расписание на сегодня

Пользователь нажимает кнопку **сегодня**.

### Формат ответа

```text
📅 Расписание на сегодня:

🕒 13:45 - 15:20
📚 ИИТ / Лекция 15
📍 Online
```

### Критерии приёмки

- показываются только пары текущего дня;
- пары отсортированы по времени;
- отображаются время, название и место;
- если пар нет, бот пишет: `Пар нет 🎉`.

---

## MUST-3. Расписание на неделю

Пользователь нажимает кнопку **неделя**.

### Формат ответа

```text
📆 Расписание на неделю:

📅 22.05
🕒 13:45 - 15:20
📚 Физическая культура
📍 Таганрог, Спортзал № 2
```

### Критерии приёмки

- показываются пары от сегодняшнего дня до следующих 7 дней;
- события отсортированы по дате и времени;
- у каждой пары есть место или текст `Не указано`.

---

## MUST-4. Место занятия

Бот должен показывать кабинет, корпус, спортзал или Online.

### Источники места

1. `LOCATION`;
2. `DESCRIPTION`, строка `Аудитория:`;
3. `Не указано`.

---

## MUST-5. Свободное время

Пользователь нажимает **свободное время**.

### Формат ответа

```text
🕓 Свободное время:

Свободно с 15:20 до 15:50
Свободно с 17:25 до 17:35
```

### Критерии приёмки

- бот берёт пары только на сегодня;
- сортирует их по времени;
- находит промежутки между окончанием одной пары и началом следующей;
- если промежутков нет, пишет: `Свободного времени между парами нет`.

---

## MUST-6. Добавление задачи

Пользователь нажимает **добавить задачу** и вводит текст.

### Критерии приёмки

- пустой текст не сохраняется;
- задача сохраняется в `tasks.json`;
- бот отвечает: `Задача добавлена`.

---

## MUST-7. Просмотр задач

Пользователь нажимает **мои задачи**.

### Критерии приёмки

- бот читает `tasks.json`;
- показывает список задач;
- если задач нет, пишет: `Задач пока нет`.

---

## SHOULD

| Требование | Описание |
|---|---|
| Разделение пользователей | У каждого Telegram-пользователя свои данные |
| SQLite | Хранение пользователей, задач и расписания в БД |
| Статусы задач | `active`, `done` |
| Дедлайны задач | дата выполнения задачи |
| Удаление задач | удаление по номеру или ID |

---

## NICE

- напоминания о парах;
- напоминания о задачах;
- настройки пользователя;
- экспорт расписания;
- команда `/help`;
- логирование ошибок.
