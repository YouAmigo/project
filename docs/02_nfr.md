# Нефункциональные требования

## Назначение

Документ описывает качество работы системы: скорость, стабильность, безопасность и поддержку.

## Производительность

| Операция | Целевое время |
|---|---:|
| Открыть меню | до 1 сек |
| Показать сегодня | до 1 сек |
| Показать неделю | до 2 сек |
| Найти свободное время | до 1 сек |
| Добавить задачу | до 1 сек |
| Загрузить `.ics` до 5 MB | до 3 сек |

Для MVP допустимо читать `.ics` при каждом запросе. После подключения БД лучше парсить `.ics` один раз при загрузке.

## Надёжность

Бот не должен падать при ошибках пользователя.

| Ситуация | Ответ |
|---|---|
| Нет расписания | Сначала загрузите расписание |
| Не `.ics` файл | Нужно загрузить файл .ics |
| Нет пар сегодня | Пар нет 🎉 |
| Нет кабинета | Не указано |
| Пустая задача | Введите текст задачи |
| Ошибка файла | Не удалось прочитать файл |

## Безопасность

Токен бота хранится только в `.env`.

```env
BOT_TOKEN=your_token_here
```

Нельзя хранить токен прямо в Python-коде.

## Хранение данных

### MVP

| Данные | Хранилище |
|---|---|
| Расписание | `.ics` |
| Задачи | `tasks.json` |
| Конфиг | `.env` |

### Улучшенная версия

| Данные | Хранилище |
|---|---|
| Пользователи | SQLite |
| Расписание | SQLite |
| Задачи | SQLite |
| Настройки | SQLite |

## Масштабируемость

Для одного пользователя достаточно файлов. Для нескольких пользователей нужно:

- добавить `users`;
- хранить `telegram_id`;
- связать расписание и задачи с `user_id`;
- добавить индексы в БД;
- ограничить размер `.ics`.

## Поддерживаемость

Рекомендуемая структура:

```text
app/
├── handlers/
├── services/
├── parsers/
├── repositories/
├── models/
├── keyboards/
└── data/
```

## Критерии качества

Проект считается стабильным, если:

- бот запускается без ошибок;
- кнопки работают;
- `.ics` загружается;
- кабинет отображается;
- задачи сохраняются;
- ошибки не ломают бота.
